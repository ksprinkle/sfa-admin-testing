SFA practical production-readiness checklist for beach-day cellular use.

Must-Have Setup

Host the API on a public URL (not laptop/local network).
Host the admin frontend on a public URL.
Use HTTPS for frontend and API.
Ensure websocket uses WSS in production.
Point frontend API base URL to production API domain.
Configure CORS to allow only your production frontend origin.
Use a managed production database with backups.
Run database migrations on deploy.
Set secure auth secrets as environment variables.
Add basic monitoring/logging so you can see API errors live.
Config Checklist

Frontend env:
VITE_API_URL=https://your-api-domain
Backend env:
DB connection string
JWT/auth secret
allowed CORS origin(s)
production mode flags
Networking:
websocket endpoint reachable through your reverse proxy
idle timeout settings that do not kill websockets too aggressively
Operational Safeguards

Keep the existing offline queue and retry logic (already done).
Keep periodic polling fallback even with websocket (already done).
Add a small “pending offline check-ins” indicator on screen (already partly present).
Add an admin “sync now” button (manual recovery path).
Set token/session expiry long enough for event day, or provide quick re-login flow.
Have a secondary admin device logged in as backup.
Beach-Day Test Script (Run Before Event)

Open app on two devices over cellular.
Confirm both load and authenticate.
Device A: airplane mode ON, check in 3 participants.
Verify queue count increases and UI updates locally.
Device A: airplane mode OFF.
Confirm queued check-ins sync automatically.
Device B: confirm changes appear without manual refresh.
Repeat with weak signal area if possible.
Force-close and reopen app with pending queue to verify recovery.
Verify no duplicate check-ins and waiver rules still enforced.
Go/No-Go Criteria

No data loss after offline -> reconnect.
Cross-device sync appears automatically within expected interval.
Queue drains to zero after reconnect.
Staff can continue checking in during network interruptions.
Backend logs show no repeated auth/CORS/websocket failures.
