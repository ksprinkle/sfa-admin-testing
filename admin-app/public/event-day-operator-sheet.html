SFA Event-Day Operator Sheet

One-page quick reference for live event operations. Updated April 22, 2026.

Use this version when you want the shortest possible decision guide during check-in operations or field testing.

Open full troubleshooting sheet

Expected

Short cross-device delay, websocket reconnect, or polling catch-up within a few seconds.

Keep going

Amber queue banner means the app saved the check-in locally and is waiting to sync.

Stop and fix

Waiver rejection means the server intentionally blocked check-in. Verify waiver first.

If queue does not clear

Wait 10 to 15 seconds after reconnect, tap Refresh once, then verify backend/network.

If another device stays stale

Wait 5 to 10 seconds, then refresh once. Persistent stale state means a real sync issue.

If app returns to login

Token expired or became invalid. Log in again and reopen the event.

Offline or dropped network

  • Expect offline notice plus amber queue banner.
  • Keep working if needed.
  • Reconnect network and leave page visible.
  • Escalate if queue survives reconnect and manual refresh.

Waiver not verified

  • Expect red waiver message naming the participant.
  • Do not treat it as a sync bug.
  • Verify waiver, then retry.

Realtime or websocket interruption

  • Expect temporary stale screen on the other device.
  • Polling should catch up shortly.
  • If not, refresh once and verify backend is running.

Use the dev panel while testing

  • Network shows effective online state.
  • Pending queue shows unsynced local check-ins.
  • Queue source shows what triggered the last retry.
  • WebSocket status shows whether live updates are connected.
